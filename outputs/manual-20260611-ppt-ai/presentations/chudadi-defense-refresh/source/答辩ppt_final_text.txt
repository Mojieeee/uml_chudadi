锄大地 Android 棋牌游戏 6. 阶段 3：细化迭代 2 / 构造（Elaboration / Construction） 45 REPORT BLOCK 5 .2 出牌规则模块 • 项目使用 RuleSet 表示规则接口，并通过 NorthRuleSet 和 SouthRuleSet 适配南北玩法差异 ： • 牌型识别由 HandClassifier 完成，支持单张、对子、三张、顺子、同花、葫芦、四带一和同花顺。GameController 在玩家出牌时调用规则模块进行合法性校验，并根据三家过牌、上一手牌和当前玩家推进牌局状态 。 • 规则模块的详细执行流程如下 ： 1. 玩家或 AI 选择若干张牌后，GameController.play () 首先判断是否轮到该玩家 。 2. 控制器调用 state.ruleSet.classify (cards) 识别牌型；无法识别时返回非法提示 。 3. 如果是首出，调用 state.ruleSet.canLead (cards, state.firstTurn ) 检查是否包含规则指定首牌 。 4. 如果是跟牌，调用 state.ruleSet.canBeat (previous, next) 判断是否可以压过上一手 。 5. 合法出牌会从玩家手牌中移除对应牌，刷新 lastMove、currentPlayerId 和提示消息 。 6. 三家连续不出后，上一手清空，下一位玩家获得自由出牌权 。 7. 某玩家手牌为 0 时，winnerId 产生，进入结算 。 使用了单例模式， RuleSet.kt 中的 object NorthRuleSet、object SouthRuleSet南北规则作为全局唯一规则对象，不需要重复创建，便于统一引用 规则项 北方规则 南方规则 首出牌 黑桃 3 首出 方块 3 首出 五张牌比较 四带一、同花顺可作为增强强牌跨牌型压制普通牌 五张牌之间按顺子、同花、葫芦、四带一、同花顺等级比较 压牌限制 根据北方增强牌规则判断 更强调同张数压制和五张牌等级 配置方式 通过规则设置保存到本机 通过规则设置保存到本机

锄大地 Android 棋牌游戏 6. 阶段 3：细化迭代 2 / 构造（Elaboration / Construction） 46 REPORT BLOCK 5 .3 蓝牙通信模块 • 多人联机采用房主权威的 C/S 模式，而不是一对一蓝牙匹配。房主手机创建房间并监听连接，加入者手机作为客户端连接房主。房间固定四个座位，房主可以添加人机补位，满四座并准备后开始游戏。 使用了适配器模式， GameTransport.kt 抽象传输接口，BluetoothHostTransport、BluetoothClientTransport、LocalRoomTransport 适配不同传输方式 ， UI 和房间逻辑不用直接依赖 BluetoothSocket，真实蓝牙和本地模拟可以共用一套调用方式 。使用了观察者模式， GameTransport.observeEvents(listener) 通过回调监听 TransportEvent.Message、PeerConnected、PeerDisconnected、Error蓝牙连接、断开、消息到达时通知上层界面或房间控制逻辑，体现事件驱动 • 蓝牙通信的核心流程 ： 1. 房主创建房间，建立 BluetoothHostTransport，持续监听加入者连接 。 2. 加入者搜索附近或已配对设备，并通过 BluetoothClientTransport 连接房主 。 3. 加入者发送 HELLO，其中包含昵称和客户端标识等基础信息 。 4. 房主维护四座位 RoomSeat，记录 SeatConnectionState、clientId、设备地址和是否由 AI 托管 。 5. 房主广播 ROOM( roomId , hostEpoch , seats)， 使所有客户端看到一致座位 。 6. 开局时房主生成 seed、同步规则并广播 START 消息 。 7. 客户端只发送 MOVE_REQUEST，不直接修改本地牌局 。 8. 房主使用 NetworkMoveGuard 判断是否为当前玩家的有效请求 。 9. 房主调用 GameController 校验和推进状态 。 10. 房主广播 MOVE_ACCEPTED 和 STATE_SNAPSHOT，所有客户端以房主快照为准刷新牌桌 。 11. 如果客户端断线，传输层发出 TransportEvent.PeerDisconnected，房主把对应座位标记为“ 断线，人机托管中 ”， 并广播 DISCONNECT_NOTICE。 12. 当前发布版没有实现自动断线重连；断线客户端需要重新进入蓝牙流程 。 13. 如果房主断线，客户端弹窗提示连接断开，关闭当前传输并退出房间，提示重新创建或重新加入 。 • 这种方式可以避免多台手机各自结算导致的状态分叉，也便于测试时用 LocalRoomTransport 和 SimulatedBluetoothHubTest 模拟多人房间。由于房主是权威端，当前版本对房主断线采用保守处理：直接提示并退出，而不尝试新房主迁移，避免恢复过程中出现多端状态不一致。
