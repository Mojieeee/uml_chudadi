# AI 工具使用说明与效果评价

## 使用者与工具

本项目由开发者本人完成需求分析、代码实现、运行测试和文档整理。开发过程中借助了 AI 工具提高效率，但关键规则、最终代码、真机运行和交付内容均由开发者确认。

实际使用的模型和工具如下：

| 工具/模型 | 使用位置 | 主要用途 |
| --- | --- | --- |
| OpenAI Codex / GPT-5 | Codex 桌面开发环境 | 需求拆解、代码生成建议、错误定位、文档同步、测试场景补全 |
| Android Studio | Android 项目开发 | Kotlin/Compose 编码、Gradle 构建、真机运行、GitHub HTTPS 推送 |
| PlantUML | UML 文本建模 | 用代码描述用例图、类图、顺序图、状态图、活动图、组件图、部署图 |
| ProcessOn UML | UML 正式绘制 | 将 PlantUML 图内容导入/参考后整理为正式 UML 图 |
| Gradle/JUnit | 自动化测试 | 运行规则、AI、蓝牙模拟、玩家成长和消息协议测试 |

## 使用阶段

1. 需求分析：开发者使用 OpenAI Codex / GPT-5 辅助阅读实训启动纲要，提炼评分点、功能范围和验收标准。
2. 架构设计：开发者借助 AI 对 MVC 分层、规则模型、AI 策略模式、蓝牙 C/S 房间拓扑和房主权威同步进行方案比较。
3. UML 建模：开发者先用 PlantUML 代码表达 7 类图，再将 PlantUML 图内容导入或参照迁移到 ProcessOn UML 中整理为正式图。
4. 编码实现：开发者在 Android Studio 中实现 Kotlin/Compose 页面、锄大地规则、三档 AI、蓝牙消息协议、玩家成长系统和 release 配置。
5. 测试排错：开发者借助 AI 补充测试场景，包括牌型识别、南北规则、AI 合法动作、房间座位、消息编解码、蓝牙模拟、金币消费和动画 key。
6. 性能优化：开发者参考 Android Compose 性能建议，并借助 AI 检查动画卡顿风险、每帧布局开销和不必要状态刷新。
7. 发布协助：开发者借助 AI 检查 debug/release 差异、release 签名证书、GitHub HTTPS remote、`.gitignore` 敏感文件排除和文档一致性。
8. 文档归档：开发者使用 AI 辅助整理需求说明、设计说明、UML 说明、测试报告、敏捷过程和最终评分检查表。

## 使用效果

AI 工具对需求归纳、代码骨架、UML 图内容和测试场景生成帮助明显，能快速把课程评分标准转化为可实现模块。尤其在蓝牙联机和 AI 策略部分，AI 辅助比较了 C/S 拓扑、房主权威同步、策略模式和 Monte Carlo Rollout 的可行性。

在 AI 辅助检查过程中，开发者发现并修正了多处不一致问题，例如旧文档引用早期 AI 类名、UML 未覆盖 `RoomSeat` 和 `StateSnapshot`、蓝牙并发加入需要模拟测试、玩家成长系统文档未覆盖金币消费二次确认等。

## 人工确认内容

以下内容由开发者人工确认或需要在最终答辩前继续确认：

- 老师对南北玩法细节的解释是否与当前 `RuleSet` 完全一致。
- 真实蓝牙在不同品牌手机和 Android 版本上的权限、配对、发现表现。
- ProcessOn UML 中最终导出的图片是否与项目内 `.puml` 和代码一致。
- 真机联机验收截图、演示视频和团队协作材料是否完整。
- GitHub 上传、开源许可和 release 签名私钥备份是否按最终提交要求完成。

## 效果评价

AI 工具适合作为需求分析、设计建模、编码实现、测试补全和文档检查的辅助工具。它提升了迭代速度，也能在变更后提醒同步文档和测试。但游戏规则、蓝牙真机稳定性、最终 UI 体验和课程报告仍必须通过开发者运行、真机验证和教师要求来最终确认。
